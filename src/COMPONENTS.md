# COMPONENTS: the markup / hooks / CSS contract

Everything below is **binding** for all agents. `src/lib/layout.mjs` emits the shell; page modules emit
page bodies; `assets/css/*` styles them; `assets/js/*` enhances them. If you need to change a name here, change
this file first and tell the other owners.

Conventions: kebab-case classes, BEM-ish `block__element` + modifier classes (`.btn-primary`, `.card--glow`).
State is expressed with `aria-*`/`data-*` attributes where one exists, otherwise `is-*` classes.
All URLs in markup are built with `ctx.url('repo/root/relative/path')`, never hand-written.

## 1. HTML shell (generated by `layout.mjs`)

```html
<!doctype html>
<html lang="en" class="no-js"  data-theme="dark|light" data-theme-pref="dark|light|system">  <!-- attrs set by inline head script -->
<head> … fonts, css (tokens, base, components, modules/*, page css), modulepreload, JSON-LD, analytics … </head>
<body data-page="home|about|experience|projects|project|contact|notfound" class="page-<id> [page.bodyClass]">
  <noscript>GTM iframe</noscript>
  <a class="skip-link" href="#main">Skip to main content</a>
  <header class="site-header" data-header>…</header>          <!-- landmark: banner -->
  <main id="main" tabindex="-1"> …page body… </main>          <!-- landmark: main (exactly one <h1> inside) -->
  <footer class="site-footer">…</footer>                      <!-- landmark: contentinfo -->
  <button class="to-top" type="button" data-to-top>…</button>
  <dialog class="palette" data-palette>…</dialog>
  <script type="application/json" id="palette-data">…</script>
  <script type="module" src="…/assets/js/main.js"></script>
  <script type="module" src="…page js…"></script>             <!-- one per entry in page.js -->
</body>
```

Document-level state:

| Selector | Meaning |
|---|---|
| `html.no-js` / `html.js` | `no-js` until the inline head script runs (before first paint), then `js`. **Only hide `[data-reveal]` under `.js`.** |
| `html.is-ready` | Added by `main.js` after all module `init()`s ran (use to start entrance choreography). |
| `html[data-theme="dark\|light"]` | Resolved theme. Default (no JS) tokens must be dark; add a `@media (prefers-color-scheme: light)` fallback under `html:not([data-theme])`. |
| `html[data-theme-pref="dark\|light\|system"]` | What the user chose. localStorage key: `theme`. |
| `html.nav-open` | Mobile menu open (header.js): lock body scroll. |
| `<meta name="theme-color" data-theme-color="dark\|light">` x2 | Two media variants. When the user picks an explicit theme the inline script/theme.js sets `content` on **both** and removes `media`. |
| `body[data-page]` | Page id. `data-page="project"` pages have `nav` = `projects`. |

Header markup (nav + actions) exactly as emitted:

```html
<header class="site-header" data-header>
  <div class="scroll-progress" data-progress aria-hidden="true"><span class="scroll-progress__bar" data-progress-bar></span></div>
  <div class="site-header__inner container">
    <a class="brand" href="index.html"><span class="brand__mark"><svg class="brand__glyph">…N drawn as a 4-node graph…</svg></span><span class="brand__name">Nikos Georgopoulos Ninos</span></a>
    <nav class="site-nav" id="site-nav" data-nav aria-label="Primary">
      <ul class="site-nav__list"><li><a class="nav-link" href="…" aria-current="page|true">Home</a></li>…</ul>
      <span class="nav-pill" data-nav-pill aria-hidden="true"></span>
    </nav>
    <div class="site-header__actions">
      <button class="icon-btn palette-trigger" data-palette-open>icon <kbd class="kbd"><span data-kbd-mod>Ctrl</span><span>K</span></kbd></button>
      <button class="icon-btn theme-toggle" data-theme-toggle><span class="theme-toggle__icon theme-toggle__icon--sun">svg</span><span class="theme-toggle__icon theme-toggle__icon--moon">svg</span></button>
      <a class="btn btn-primary btn-sm header-cta" href="contact.html">Let's talk</a>
      <button class="icon-btn nav-toggle" data-nav-toggle aria-expanded="false" aria-controls="site-nav"><span class="nav-toggle__icon nav-toggle__icon--open">svg</span><span class="nav-toggle__icon nav-toggle__icon--close">svg</span></button>

```

`aria-current="page"` = this page; `aria-current="true"` = parent section (project detail pages mark Projects).
Style `.nav-link[aria-current]` as active. Mobile (< 900px): `.site-nav` becomes a dropdown panel shown when
`.site-header[data-nav-open="true"]`; `.nav-toggle` is hidden >= 900px; `.header-cta` is hidden < 600px.

Footer: `.site-footer` > `.container` > `.site-footer__grid` (`.site-footer__brand` with `.brand` + `.site-footer__blurb`;
`nav.site-footer__col` + `.site-footer__heading` + `ul.site-footer__list` of `a.link-arrow`; `.site-footer__col` with
`ul.site-footer__list.site-footer__socials` of `a.social-link` (svg + span)) and `.site-footer__bottom` (`p` + `p.site-footer__note`).

## 2. Hooks the JS modules rely on

### 2.1 Header / navigation (`modules/header.js`)

| Hook | Behaviour / what JS writes |
|---|---|
| `[data-header]` | JS sets `data-scrolled="true"` when `scrollY > 8`; `data-hidden="true"` while scrolling down past 240px (removed on scroll up, on focus-within, when nav open); `data-nav-open="true\|false"`. |
| `[data-progress]` | JS sets CSS var `--progress` (0..1) on it. CSS: `.scroll-progress__bar{transform:scaleX(var(--progress,0));transform-origin:left}`. |
| `[data-nav] .nav-link` | Hover/focus moves the pill; leave returns it to the `[aria-current]` link. |
| `[data-nav-pill]` | JS sets `--pill-x`, `--pill-w` (px values with unit) and `data-visible="true"`. CSS positions it absolutely inside `.site-nav{position:relative}` with `transform:translateX(var(--pill-x))`, `width:var(--pill-w)`. Must also look right with JS off (hidden). |
| `[data-nav-toggle]` | Toggles `aria-expanded`, `.site-header[data-nav-open]`, `html.nav-open`, `aria-label` ("Open menu"/"Close menu"). Closes on Esc, link click, resize >= 900px. |
| `[data-spy]` | Optional scroll-spy container: `<a href="#id">` links inside it get `aria-current="location"` for the section in view. |
| `[data-header][data-hide-on-scroll="false"]` | Opt a page out of hide-on-scroll (default: the header hides while scrolling down, `data-hide-on-scroll` is read from the header element). |
| `[data-to-top]` | JS sets `data-visible="true"` once `scrollY > 600`; click scrolls to top (smooth unless reduced motion) and focuses `#main`. CSS: hidden unless `[data-visible="true"]` (under `.js`). |

### 2.2 Theme (`modules/theme.js`)

* `[data-theme-toggle]`: click flips the resolved theme (dark <-> light) and stores an explicit preference. **Shift-click or Alt-click resets the preference to `system`** (follow the OS) and shows a toast. Updates its own `aria-label` ("Switch to light/dark theme").
* theme.js exports `getTheme()` (`{pref, theme}`), `setTheme(pref)`, `toggleTheme()` and dispatches `document` event `themechange` with `detail: {pref, theme}` (the canvas listens to it). `window.setTheme` is also assigned.
* CSS shows `.theme-toggle__icon--sun` when `[data-theme="dark"]` (click -> light) and `--moon` when light.

### 2.3 Command palette (`modules/palette.js`)

Opens with `Ctrl/Cmd+K` anywhere, or `/` when focus is not in an input/textarea/contenteditable, or any `[data-palette-open]`.
`[data-kbd-mod]` text is replaced with `⌘` on Apple platforms.

Dialog skeleton (static, emitted by layout):

```html
<dialog class="palette" data-palette aria-label="Command palette">
  <div class="palette__box">
    <div class="palette__search">svg <input class="palette__input" data-palette-input role="combobox" aria-expanded="true" aria-controls="palette-list" aria-autocomplete="list"> <kbd class="kbd">esc</kbd></div>
    <ul class="palette__list" id="palette-list" role="listbox" data-palette-list></ul>
    <p class="palette__empty" data-palette-empty hidden>No results…</p>
    <div class="palette__foot">…key hints…</div>
  </div>
</dialog>
```

palette.js renders into `[data-palette-list]` (suggested item classes, CSS agent must style them):
`.palette__group` (heading row: Pages / Projects / Actions), `.palette__item` (`[aria-selected="true"]` = active, `[role="option"]`),
`.palette__item-icon`, `.palette__item-title`, `.palette__item-hint`, `mark` for matched characters. Use `dialog.showModal()`;
style `.palette::backdrop`. Focus is returned to the opener on close. Set `aria-activedescendant` on the input.

`<script type="application/json" id="palette-data">` schema (URLs are **already rebased** for the current page):

```jsonc
{
  "current": "projects",                        // nav id of the current page (boost / mark it)
  "pages":    [{ "id", "title", "url", "icon", "hint" }],
  "projects": [{ "id", "title", "url", "icon", "hint" /* categories */, "keywords" }],
  "actions":  [{ "id", "title", "icon", "keywords",
                 "action": "toggle-theme" | "copy" | "open" | "print",
                 "value"?: "text to copy",      // action: copy
                 "url"?: "…", "external"?: true, // action: open / print
                 "hint"?: "…" }]
}
```

Action semantics: `toggle-theme` -> `toggleTheme()` from theme.js; `copy` -> `copyText(value)` + `toast`; `open` -> `location.assign(url)`
(or `window.open(url,'_blank','noopener')` when `external`); `print` -> if `body[data-page="experience"]` call `window.print()`,
else navigate to `url` (`experience.html?print=1`). **experience.js must auto-call `window.print()` when `?print=1` is present** (after fonts load).

### 2.4 Toast and copy (`modules/core.js`)

* `toast(message, {type:'info'|'success'|'error', duration})` also as `window.toast`. Creates `<div class="toast-region" data-toast-region role="status" aria-live="polite">` once;
  each toast: `<div class="toast [is-in|is-out]" data-type="info|success|error"><span class="toast__icon" aria-hidden></span><span class="toast__message">…</span></div>`.
  The CSS draws the icon (via `data-type`), positions the region (bottom centre, above `.to-top`), animates `.is-in`/`.is-out`.
* `[data-copy="text"]` (empty value = element's own text). Optional `data-copy-message`, `data-copied-label` + a child `[data-copy-label]` whose text is swapped for ~1.8s. State: `data-copied="true"`. Fires bubbling `copied` event.

### 2.5 Reveal, count-up, timeline, marquee (`modules/reveal.js`)

| Hook | Contract |
|---|---|
| `[data-reveal]` | Values: `""`/`up` (default), `left`, `right`, `zoom`, `fade`. JS adds `.is-visible` once intersecting (once only). CSS: `.js [data-reveal]{opacity:0;transform:…per variant…;transition-delay:var(--reveal-delay,0ms)}` and `.js [data-reveal].is-visible{opacity:1;transform:none}`. Under reduced motion JS marks everything `.is-visible` immediately and CSS must not hide. |
| `data-delay="120"` | ms; JS writes `style="--reveal-delay:120ms"`. |
| `[data-reveal-stagger]` | Parent. JS assigns `--reveal-delay` = index x step to each descendant `[data-reveal]` that is a direct child (step = `data-stagger`, default 70ms). |
| `[data-count="16"]` | Count-up on first view. Text content is pre-rendered with the **final** value (+suffix) for no-JS/SEO. Optional `data-suffix="+"`, `data-decimals="1"`, `data-duration="1400"`. Uses `Intl.NumberFormat('en')`. Under reduced motion: left as is. |
| `[data-timeline]` | On the `div.timeline` wrapper. JS writes `--timeline-progress` (0..1) on it as the section scrolls. |
| `[data-timeline-progress]` | The filled bar inside `.timeline__line` (see 3.2); CSS `transform:scaleY(var(--timeline-progress,0))`. Items alternate sides from `>= 900px` via `.timeline-item:nth-child(even)`. |
| `.marquee` | **CSS only** (see section 3). JS is not required. |

### 2.6 Pointer effects (`modules/pointer-fx.js`, fine pointers only, never under reduced motion)

| Hook | Contract |
|---|---|
| `.card`, `[data-spotlight]` | One delegated `pointermove` on `document` (rAF-throttled). Writes `--mx`, `--my` (px, relative to the card under the pointer) and toggles `.is-spotlit`. CSS paints a radial gradient (border + glow) at `var(--mx) var(--my)`. |
| `[data-tilt]` | Max 6deg (`data-tilt-max`), writes `--tilt-x`, `--tilt-y` (deg, with unit) and `--glare-x`, `--glare-y` (%); adds `.is-tilting`. CSS: `transform:perspective(900px) rotateX(var(--tilt-x,0deg)) rotateY(var(--tilt-y,0deg))` with a smooth transition when not `.is-tilting`. `data-tilt-glare` enables a `.tilt-glare` child (optional). |
| `[data-magnetic]` | Strength `data-magnetic-strength` (default .25). Writes `--magnet-x`, `--magnet-y` (px with unit). CSS: `transform:translate(var(--magnet-x,0px),var(--magnet-y,0px))`. |

### 2.7 Hero effects (`modules/hero.js`)

* `[data-typed='["Software Engineer","Developer",…]']`: JSON array in the attribute. **The element's initial text is the first role** (no-JS/SEO). Optional `data-typed-speed` (ms/char, default ~70), `data-typed-pause` (ms, default 1600). JS replaces the content with `.typed__live[aria-hidden]` > `.typed__text` + `i.typed__caret`, one invisible `.typed__ghost` per role (all share one inline-grid cell, so the width of the longest role is reserved: no layout shift), and a `.sr-only` span listing all roles; it sets `data-typed-ready="true"`, pauses when off-screen, and keeps the static first role under reduced motion. Caret blink is CSS (`@keyframes`).
* `[data-scramble-load]`: text decoded once on load (e.g. the hero name). Markup must carry `aria-label="<real text>"`; JS sets `aria-hidden` on the scrambling inner span. `[data-scramble]`: scramble on hover/focus (links).
* `canvas[data-network]` (`aria-hidden="true"`, inside `.hero`): node network. Reads colours from CSS vars `--network-node`, `--network-line`, `--network-accent` (re-read on `themechange`). Optional `data-network-density`. Single static frame under reduced motion; pauses when off-screen / tab hidden; DPR capped at 2.

### 2.9 Lightbox (`modules/lightbox.js`, loaded by `main.js` only when `[data-lightbox]` exists)

```html
<ul class="gallery" data-lightbox>
  <li><a class="gallery__item" href="assets/img/…/full.png" data-lightbox-src="assets/img/…/full.png" data-lightbox-alt="…" data-lightbox-caption="…">
        <img src="…" alt="…" width="…" height="…" loading="lazy" decoding="async"></a></li>
</ul>
```
A trigger may be an `<a href>` (project pages: the link opens the full image when JS is off) or a `<button type="button">`; the script only looks for `[data-lightbox-src]` inside the `[data-lightbox]` group and prevents the default navigation.
`data-lightbox-src` is an already-rebased URL (`ctx.url(...)`). JS builds one `<dialog class="lightbox" data-lightbox-dialog>` appended to `body`:
`.lightbox__figure` > `img.lightbox__img` + `figcaption.lightbox__caption`; `button.lightbox__btn.lightbox__close|__prev|__next`; `.lightbox__counter`.
Arrow keys / Esc / swipe, focus trap + return focus to the trigger.

### 2.11 Forms (`pages/contact.js`)

```html
<div class="form-status" data-form-status role="status" aria-live="polite">
  <div class="alert alert--success contact-panel contact-panel--success" id="form-sent" data-panel="success" tabindex="-1">… <button data-form-reset>Send another message</button></div>
  <div class="alert alert--error contact-panel contact-panel--error" data-panel="error" tabindex="-1">…</div>
</div>
<form class="contact-form" data-contact-form action="{site.formEndpoint}" method="POST"
      data-ajax-endpoint="{site.formAjaxEndpoint}" data-name-min="2" data-message-min="10" data-message-max="2000">
  <input type="hidden" name="_subject" value="…"> <input type="hidden" name="_captcha" value="false">
  <input type="hidden" name="_template" value="table">
  <input type="hidden" name="_next" value="{site.url}/contact.html?sent=1#form-sent">
  <div class="sr-only" aria-hidden="true"><label>…<input type="text" name="_honey" tabindex="-1" autocomplete="off"></label></div>
  … <div class="form-field contact-field" data-field> label.form-field__label + .input + p.form-field__error[role=alert] </div>

```
Without JS the form POSTs to formsubmit.co, which redirects back to `_next`; `#form-sent` plus the `?sent=1` flag reveals the success panel (CSS `:target` fallback / `contact.js`). With JS, `contact.js` validates inline, posts to `data-ajax-endpoint`, shows the success/error panel (only one visible at a time), toggles `.btn[aria-busy="true"]`, and strips `?sent=1` / `#form-sent` afterwards.

## 3. Shared CSS vocabulary (`assets/css/components.css`; tokens in `tokens.css`)

### 3.1 Tokens that must exist (names are consumed by JS and page CSS)
Colour: `--bg --bg-elev --bg-sunken --surface --surface-hover --border --border-strong --text --text-muted --text-subtle --accent --accent-2 --accent-violet --accent-contrast --grad-accent --focus-ring --network-node --network-line --network-accent`.
Shape/space: `--radius-sm|md|lg|xl|pill`, `--space-1…--space-12`, `--container` (≈1180px), `--container-narrow` (≈760px), `--gutter` (fluid), `--header-h`.
Type: `--font-sans --font-display --font-mono`, `--fs-xs|sm|base|md|lg|xl|2xl|3xl|4xl|display` (clamp), `--lh-tight|base|loose`.
Motion/depth: `--ease-out` (`cubic-bezier(.2,.8,.2,1)`), `--dur-fast|base|slow` (160/280/560ms), `--shadow-sm|md|lg`, `--glow`, `--z-base|header|palette|toast|top`.
Breakpoints (documented, used literally in media queries): 600, 900, 1200px.

### 3.2 Components (class -> intended markup)

**Layout**
* `.container` (+ `--narrow`, `--wide`): centred, `padding-inline: var(--gutter)`.
* `.section` (+ `--tight`, `--alt` tinted band, `--flush-top`): vertical rhythm. Gradient-mesh blobs are decorative `::before/::after` or `.section__blob` spans (`aria-hidden`).
* `.section-head`: `<header class="section-head [section-head--center|--split]"><p class="eyebrow"><span class="eyebrow__index">01</span><span class="eyebrow__label">About</span></p><h2 class="section-title">…</h2><p class="section-lede">…</p></header>`. `--split` puts a `.link-arrow` on the right.
* `.page-hero` (inner pages): `<header class="page-hero"><div class="container"><p class="eyebrow">…</p><h1 class="page-hero__title">…</h1><p class="page-hero__lede">…</p></div></header>`.
* `.grid` + `--2|--3|--4` (collapse: 4>2>1, 3>2>1) + `--auto` (`repeat(auto-fit,minmax(var(--min,16rem),1fr))`); `.stack` (vertical flow, `--stack-gap`); `.cluster` (flex-wrap row, gap); `.gap-sm|.gap-lg`.
* Utilities: `.sr-only`, `.skip-link` (visible on focus), `.text-center`, `.muted`, `.mono`, `.text-gradient`, `.display` (hero scale), `.divider`, `.kbd`.

**Surfaces**
* `.card` (+ `--glow`, `--flat`, `--interactive` hover lift, `--pad-lg`): glass surface with cursor spotlight (`--mx/--my`). Parts: `.card__media`, `.card__body`, `.card__title`, `.card__meta`, `.card__footer`.
* `.callout` (+ `--accent`): `<aside class="callout"><p class="callout__label">My key characteristic</p><p class="callout__text">…</p></aside>`.
* `.stat`: `<div class="stat"><span class="stat__icon">svg</span><span class="stat__value" data-count="9">9</span><span class="stat__label">Projects</span></div>`; place in `.grid.grid--4`.
* `.quote`: `<figure class="quote card"><svg quote/><blockquote class="quote__text"><p>…</p></blockquote><figcaption class="quote__author"><strong>Name</strong><span class="quote__role">Role</span></figcaption></figure>`.
* `.cta-band`: closing call-to-action band (`.cta-band__title`, `.cta-band__text`, `.cta-band__actions`).
* `.meta-list`: `<dl class="meta-list"><div class="meta-list__item"><dt class="meta-list__label">Client</dt><dd class="meta-list__value">…</dd></div>…</dl>` (about facts, project meta panel).
* `.photo-frame`: framed portrait/cover image wrapper with gradient ring (`.photo-frame__img`).
* `.alert` (+ `--success`, `--error`), `.empty-state`.

**Actions**
* `.btn` + `.btn-primary` (gradient fill, dark text) | `.btn-ghost` (outline/glass); sizes `.btn-sm`, `.btn-lg`; `.btn-icon` (square icon-only); an `svg.icon` inside a `.btn` is sized `1.1em` and gap-spaced; `[aria-busy="true"]` shows a spinner; works as `<a>` or `<button>`. `data-magnetic` allowed.
* `.icon-btn`: round 40px glass icon button (header actions, carousel arrows).
* `.link-arrow`: inline text link that draws its own arrow with `::after` and nudges it on hover. **Do not put an svg inside.**
* `.social-link`: icon + label link (footer, contact).

**Labels**
* `.chip` (+ `--sm`, `--mono`): pill; becomes a filter toggle with `[aria-pressed="true"]` (active) and an optional `.chip__count`.
* `.tag`: tiny mono label for technologies (`ul.tag-list > li.tag`). `.badge` (+ `--accent`, `--success`, `--muted`) with optional `.badge__dot` (pulse) e.g. "Available", "Present".
* `.eyebrow` (mono, uppercase, `__index` + `__label`).

**Content**
* `.prose`: long-form text (max ~68ch), lists, links, `blockquote`.
* `.numbered-list`: `ol` with big mono counters (project contributions).
* `.timeline` (valid markup: a `div` wrapper, the line, then the list):
  ```html
  <div class="timeline" data-timeline>
    <span class="timeline__line" aria-hidden="true"><span class="timeline__progress" data-timeline-progress></span></span>
    <ol class="timeline__list">
      <li class="timeline-item" data-reveal>
        <span class="timeline-item__marker" aria-hidden="true"></span>
        <div class="timeline-item__card card">
          <p class="timeline-item__period">07/2022 – present</p>
  ```

## 4. Page module API (`src/pages/<page>.mjs`)

```js
import { html, raw } from '../lib/html.mjs';
import { icon } from '../lib/icons.mjs';

export default function render(ctx, pageArg) {   // pageArg: the project object for project.mjs, otherwise undefined
  return {
    id: 'about',                // required. Becomes <body data-page>; also the nav id when `nav` omitted
    path: 'about.html',         // required; must equal the planned output path (build.mjs checks)
    title: 'About',             // required except for home. Rendered "About · Nikos Georgopoulos Ninos" (home: "Name — Title")
    description: '…',           // meta/OG/Twitter description (defaults to site.seo.description)
    body: html`…`,              // required: html`` or raw() result (a plain string would be escaped)
    css: ['assets/css/pages/about.css'],   // repo-root-relative; appended after the shared CSS
    js:  ['assets/js/pages/about.js'],     // loaded as <script type="module"> after main.js
    nav: 'projects',            // optional: nav item to mark aria-current="true" (project detail -> projects)
    bodyClass: '', ogImage: 'assets/img/…', ogImageAlt: '…', ogType: 'article',
    breadcrumbs: [{name, path}],            // optional, emits BreadcrumbList JSON-LD
    jsonLd: [ {…} ],                        // optional extra JSON-LD objects
    preload: [{ as: 'image', href: 'assets/img/me.jpg' }],   // optional <link rel=preload>
    noindex: true, fullTitle: '…'           // optional overrides
  };
}
```

`ctx` (per page) = everything in `src/lib/content.mjs` (`site, nav, experience, education, certificates, skills,
softSkills, testimonials, projects, featuredProjects, categories, categoriesWithAll, projectBySlug, getProject, prevNext`)
**plus** `ctx.url(path)` (rebase a repo-root-relative path for this page; external/`#`/`?` pass through), `ctx.abs(path)`
(absolute canonical URL), `ctx.base`, `ctx.path`, `ctx.year`.
Rules: every interpolation is escaped by `html```; use `raw()` only for trusted markup you built (icons are already `Raw`).
`site.stats[].value` is already a number (auto stats resolved). Use `formatDate`/`slugify`/`joinUrl` from `html.mjs`.
`404.html` is rendered with `ctx.base === '/'`, so **everything** there is root-absolute (it can be served from any depth).

## 5. Adding things

* **A project**: create `content/projects/<slug>.json` (copy an existing file; `slug` must equal the filename, `order` decides sorting, `featured:true` puts it on the home page, `legacyPaths` creates redirects). Put images under `assets/img/portfolio/…` and reference them repo-root-relative. Run `node src/build.mjs`; the detail page, grid card, palette entry, prev/next links and sitemap entry appear automatically. Build fails loudly (file + JSON path) on missing fields or images.
* **A page**: create `src/pages/<name>.mjs` (API above), import it in `src/build.mjs` and add `{ id, out, render, sitemap }` to `STATIC_PAGES`; add a `NAV` entry in `src/lib/content.mjs` if it belongs in the menu; create its CSS/JS under `assets/css/pages` / `assets/js/pages`.
* **An icon**: add a 24x24 stroke glyph to `GLYPHS` in `src/lib/icons.mjs` (it is then valid in content JSON).
* **A shared JS module**: add it under `assets/js/modules/`, export `init()`, register it in `MODULES` in `assets/js/main.js` (optionally with a `when` selector so it only loads where needed).

## 6. Changes by designer

Written by the design/home agent. These supersede the wording above where they differ.

### 6.1 Reveal gating (IMPORTANT for `modules/reveal.js`)

`[data-reveal]` content is hidden **only** under `html.js.reveal-ready` (not under `html.js` alone), so a missing or failed
reveal module can never leave content invisible. **reveal.js must add the class `reveal-ready` to `<html>` as soon as its
IntersectionObserver is live** (before observing), then add `.is-visible` to elements as they intersect. Reveal animates
the individual `translate` / `scale` / `opacity` properties (not `transform`), so it composes with hover lifts, 3D tilt and
magnetic buttons that use `transform`. Under `prefers-reduced-motion` the CSS shows everything regardless.
`.timeline__progress` is a full line until `reveal-ready` is set; after that it follows `--timeline-progress` (0 default).

### 6.2 CSS file ownership and layers

* The design agent wrote **all** shared CSS: `tokens.css`, `base.css`, `components.css` **and** `modules/{header,reveal,hero,pointer,palette,toast}.css`
  (those placeholders said "the design-system agent writes the real file"). JS agents must not edit them; ask for hooks instead.
* Cascade layers are declared in `tokens.css`: `@layer reset, base, components, utilities, pages;`. All shared css lives in a layer;
  **page css (`assets/css/pages/*.css`) is unlayered and therefore always wins over shared css** without specificity games.
  Theme token blocks are unlayered too (a rule inside a layer cannot override a token declared in `:root`; see the print block).
* Colour tokens are defined three times (dark, `[data-theme="light"]`, and `:root:not([data-theme])` + `prefers-color-scheme: light` for no-JS).
  New colour tokens must be added to all of them (tokens.css is generated by hand, keep the blocks identical).
* New tokens beyond section 3.1: `--bg-elev/--band/--surface-strong/--panel-bg/--header-bg/--input-bg/--scrim`, `--accent-soft/--accent-line/--accent-glow`,
  `--violet-soft/--violet-line`, `--success/--danger/--warning (+ -soft/-line)`, `--grad-text`, `--spot-border/--spot-glow`, `--mesh-a/b/c`, `--grid-line`, `--noise-img`,
  `--section-y`, `--ease-in-out/--ease-spring`, `--tracking-tight/--tracking-mono`, `--lh-snug`, `--container-wide`, `--fs-*` extras. `--grad-accent` is a *fill*
  (bright in both themes, use `--accent-contrast` text on it); `--grad-text` is the *text* gradient (darker in light theme).

### Changes by JS agents: reveal / count-up / timeline / pointer effects (reveal-agent)

`modules/reveal.js` (exports `init()`, `refresh(scope = document)`, `countUp(el)`):

* **Gating.** `html.reveal-ready` is added only when `IntersectionObserver` exists and reduced motion is off. Elements already on screen
  (or scrolled past) at init get `.is-visible` *before* the class is added, so nothing flashes. Safety nets: a 4s timer reveals everything
  if the observer never answers; `beforeprint` and a runtime switch to reduced motion reveal everything; a cheap scroll sweep reveals
  elements that were jumped over (anchor links). Call `refresh(container)` after injecting new `[data-reveal]` markup.
* **Delays.** `data-delay="120"` -> `--reveal-delay:120ms`. Children of `[data-reveal-stagger]` (direct `[data-reveal]` children only) get
  `--reveal-index` (0,1,2...) and a static `--reveal-delay` = index x `data-stagger` (default 70ms, capped at 560ms); while scrolling the
  delay is recomputed per batch so only siblings that enter together cascade. An explicit `data-delay` always wins.
* **Count-up.** `[data-count="16"]` + optional `data-suffix`, `data-decimals`, `data-duration` (default 1400ms), `data-locale` (default `en`).
  Pre-render the final text. JS shows `0` until the element is 40% in view, eases to the target (easeOutQuart), starts after the
  enclosing `[data-reveal]`'s delay, then restores the original server-rendered text exactly. Restart-safe via `countUp(el)`.
  Reduced motion / no IO: the final text is simply left alone.
* **Timeline.** Markup is the one in section 3.2. `[data-timeline]` gets `--timeline-progress` (0..1) = how far the reading line (viewport
  centre; override with `data-timeline-offset="0.4"`) has travelled down `.timeline__line`. Each `.timeline-item` gets `.is-active` once its
  `.timeline-item__marker` is above the line, and the latest one also gets `.is-current`. Marker styling for these states lives in
  `modules/reveal.css` (only under `reveal-ready`). At the very bottom of the page with the rail fully on screen the rail completes.
  Reduced motion: full rail, every item `.is-active`, no scroll listeners. Only timelines near the viewport are measured on scroll.
  Bare `data-reveal` items of a two-sided timeline (>= 900px, not `.timeline--single`) enter from their own side automatically
  (odd = left, even = right); explicit `data-reveal="left|right"` still wins.

`modules/pointer-fx.js` (exports `init()`): one passive `pointermove` on `document` plus one passive `scroll` listener; one rAF per frame,
all layout reads before writes. Touch pointers, coarse-pointer devices and reduced motion are ignored (checked live). Everything resets
when the pointer leaves the window, the tab blurs or hides, or a modal `<dialog>` is open (magnetic only).

* `.card` / `[data-spotlight]`: `--mx`, `--my` in px relative to the element, `.is-spotlit` on the element under the pointer (also
  re-evaluated while scrolling under a still pointer). On leave only the class is removed, so the glow fades out in place.
* `[data-tilt]`: `--tilt-x`, `--tilt-y` (deg), `--glare-x`, `--glare-y` (%), `.is-tilting` while the pointer is on it, and `.is-tilt-on`
  from entry until ~750ms after the eased return. **`pointer.css` applies the 3D transform only under `.is-tilt-on`**: at rest the element
  has `transform: none` (crisp text, no permanent compositor layer). `data-tilt-max` (deg, default 6). `data-tilt-glare` makes JS append
  `<span class="tilt-glare" aria-hidden="true">` (the element must be positioned; `.card` is). Reveal uses `translate`/`scale` and floats use
  `translate`, so they combine with `[data-reveal]` and float animations without conflicts. Links inside tilted elements keep working.
* `[data-magnetic]`: `--magnet-x`, `--magnet-y` (px). Active within `data-magnetic-pad` (default 28px) of the element; `data-magnetic-strength`
  (default .25) and `data-magnetic-max` (default 12px, per axis) shape it. The element's own CSS must consume the variables
  (`.btn` / `.icon-btn` already do; other elements get a transform from `pointer.css`).
